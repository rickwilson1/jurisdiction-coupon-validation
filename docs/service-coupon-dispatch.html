What this service does

After a customer completes an order on shop.agromin.com using an Agromin program coupon, CIMcloud emails a "Pending Approval for Order Number XXXXX" HTML notification to sales@agromin.com. A Power Automate flow watches the OCWR subfolder of that mailbox, parses the email body, and POSTs the raw HTML to this service.

This service parses the HTML, decides how to fulfill the order, sends the right emails, writes the order to Firestore, and returns structured row data for Power Automate to append to Greg's SharePoint spreadsheet.

It does not validate coupons — that happens upstream in coupon-validator at checkout. By the time an order arrives here, it is a confirmed program order.

Order processing flow

Receive & parse email
Power Automate POSTs the raw CIMcloud HTML body to /api/ingest-cimcloud-email. BeautifulSoup parses customer name, email, phone, addresses, shipping method, coupon code, and line items. Non-program emails (no Coupon Code: field) are skipped silently.
Determine routing
Inspects shipping_method for the word "Delivery" (case-insensitive).
If delivery → infer region from shipping address (OC / Ventura / Sacramento).
If pickup → sum line item qty: <5 yd = self-load, ≥5 yd = staff-load.
Write to Firestore
Document keyed by order_number in the order_events collection. Records routing, region, material, qty, customer contact, and processed timestamp. Non-fatal on failure — email still sends.
Send customer email
Microsoft Graph API sends as dispatch@agromin.com. Template chosen by routing (self-load / staff-load / delivery). Ofelia (OCWR liaison) is CC'd on every customer email.
Send coordinator alert (delivery orders only)
Separate email to coordinator team — includes customer name, phone, email, address, material, qty, and coupon code. Recipients vary by region.
Return master_sheet_rows
Response includes an array of row dicts (one per line item) for Power Automate to append to Greg's OCWR-Agromin Deliveries.xlsx → Table1. Empty array for pickup orders.

Routing outcomes

pickup_self_load
Trigger: no "Delivery" in shipping_method AND total qty < 5 yd
  • Customer email: self-load pickup instructions + yard address/hours
  • SB1383 QR note included if yard has a QR sign deployed
  • No coordinator alert
  • No spreadsheet row
pickup_staff_load
Trigger: no "Delivery" in shipping_method AND total qty ≥ 5 yd
  • Customer email: staff-load pickup instructions (truck/trailer required)
  • No SB1383 QR note
  • No coordinator alert
  • No spreadsheet row
delivery
Trigger: "Delivery" appears anywhere in shipping_method
  • Customer email: delivery confirmation
  • Coordinator alert sent to regional team
  • Spreadsheet row(s) returned in response
  • Region inferred from shipping address

Endpoints

POST /api/ingest-cimcloud-email Primary — called by Power Automate
Accepts the raw HTML body of a CIMcloud "Pending Approval" email. Parses it server-side, runs the full routing + email + Firestore pipeline, and returns structured response including master_sheet_rows.
Auth: X-API-Key: $DISPATCH_API_KEY
Body (Power Automate): Content-Type: text/html + optional X-Email-Subject header — raw HTML.
Body (curl/test): Content-Type: application/json → {"body": "<html>...", "subject": "..."}
Skip response: {"status": "skipped", "reason": "..."} — non-program emails silently ignored, Power Automate loop runs zero times.
POST /api/ingest-order Structured JSON variant
Same pipeline as /api/ingest-cimcloud-email but accepts a pre-parsed OrderPayload JSON object. Used for direct API testing without a real email.
Auth: X-API-Key: $DISPATCH_API_KEY
Body: OrderPayload JSON — see schema below.
POST /api/generate-manifest
Generates a PDF delivery manifest for a hauler. Returns binary PDF bytes directly. Manifest includes order #, customer name/phone/address, material, quantity, coupon code, hauler signature line, and OCWR loader verification line.
Auth: X-API-Key: $DISPATCH_API_KEY
Body: OrderPayload JSON
Response: Content-Type: application/pdf · Content-Disposition: attachment; filename=manifest_{order_number}.pdf
Library: reportlab (pure Python — no system dependencies)
GET /api/delivery-schedule
Returns all delivery orders from the last 7 days, queried from Firestore order_events. Intended for a Cloud Scheduler trigger (weekly Ofelia summary).
Auth: X-API-Key: $DISPATCH_API_KEY
Response: {"deliveries": [{order_number, customer_name, shipping_address, material, total_qty, region, processed_at, ...}]}
GET /health
Returns {"status": "healthy", "service": "coupon-dispatch"} with HTTP 200.

Used by /api/ingest-order and /api/generate-manifest. The /api/ingest-cimcloud-email endpoint builds this internally from the HTML.

  "order_date":     "4/16/2026 11:38:23 AM PT",
  "coupon_code":    "CITYOJAICM26",
  "payment_method": "No Payment Required",
  "customer_name":  "Coline Tabrum",
  "customer_email": "coellii@yahoo.co.nz",
  "customer_phone": "805-640-0650",     // optional
  "billing_address":"1242 Anita Ave, Ojai, CA 93023",
  "shipping_address":"1940 E Ojai Ave, Ojai, CA 93023",
  "shipping_method":"Bag Pick Up at Aqua-Flo Ojai",
  "line_items": [
    {
      "sku":         "ES2",
      "description": "Cover Mulch",
      "qty":         20,                // cubic yards for bulk material

Routing key: shipping_method containing "Delivery" (case-insensitive) → delivery route. All other values → pickup route. Qty threshold for self vs. staff load: 5 cubic yards.

Infrastructure

Email — Microsoft Graph API

App-only client-credentials flow via MSAL. Token cached until 60 s before expiry. Sends as dispatch@agromin.com only — RBAC-scoped in Exchange Online. Graph creds: GRAPH_TENANT_ID, GRAPH_CLIENT_ID, GRAPH_CLIENT_SECRET. If any are unset, email is skipped with a warning log (safe for local dev).

Firestore

Collection: order_events. Document ID = order_number. Authenticated via Cloud Run default service account. Role required: Cloud Datastore User. Write failures are non-fatal — logged but do not stop email dispatch.

HTML parser

BeautifulSoup4 parses CIMcloud email HTML. Auto-detects and decodes quoted-printable encoding. Extracts fields by label matching in <td> cells and line-item table detection via header keywords (Qty, Description, Unit Price).

PDF manifest

reportlab — pure Python, no system dependencies. Letter size, 0.85" margins. Returns binary PDF as application/pdf response.

Power Automate integration

Flow lives in Rick Wilson's Environment (not Agromin default) — flow name: Agromin Order Dispatch.
StepActionDetail
1 Trigger "When a new email arrives in a shared mailbox (V2)" · mailbox: sales@agromin.com · folder: OCWR
2 HTTP POST Raw HTML body → /api/ingest-cimcloud-email with X-API-Key. Content-Type: text/html.
3 Parse JSON Reads Cloud Run response — extracts master_sheet_rows array.
4 Apply to each Loops over master_sheet_rows. Pickup orders produce an empty array → loop runs zero times.
5 Add a row into a table Excel Online (Business) · Site: OCWRxAgromin · File: Delivery Requests/OCWR-Agromin Deliveries.xlsx · Table: Table1 · All 23 columns bound by header name.

To manually trigger for testing: send a CIMcloud-formatted email to sales@agromin.com, then drag it into the OCWR subfolder in Outlook. Power Automate fires within ~60 seconds.
