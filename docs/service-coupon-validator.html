What this service does

When a customer enters a coupon code at shop.agromin.com, CIMcloud calls this service before allowing the order to proceed. The service geocodes the customer's address, maps it to a California CDTFA tax district, and confirms the coupon is valid for that location.

It is a pure validation gate — it does not send email, log orders, or trigger fulfillment. Those responsibilities belong to coupon-dispatch, which runs separately after the order is confirmed.

Validation logic — /api/validate-coupon

Coupon lookup
Normalize code to uppercase. Check the loaded coupon dataset — return denied immediately if not found.
Status check
Coupon Program Status field must equal Active (case-insensitive). Inactive or expired records are rejected.
Date range check
Today must fall within the coupon's Start Date and End Date. Either bound may be open-ended (null = no limit).
Geocode address
ArcGIS World Geocoding Service → lat/lon + canonical matched address. Returns error if the address cannot be geocoded.
CDTFA shapefile lookup
Point-in-polygon against the 26 MB CDTFA_TaxDistricts.gpkg bundled in the container. Returns city name and county name for the address.
Jurisdiction match
City coupons: address city must match the coupon jurisdiction (normalized, prefix-stripped).
County coupons: address must be in the unincorporated portion of that county (no city match → accepted; city match → denied).

Endpoints

GET /api/validate-coupon Primary
Full coupon + address validation. Called by CIMcloud at checkout. Runs all six checks above.
Query params: coupon (code string), address (full CA address)
Response: {"status": "accepted"|"denied"|"error", "coupon": "...", "jurisdiction": "...", "matched_address": "...", "reason": "..."}
GET /api/validate
Address-only jurisdiction lookup — no coupon check. Returns what CDTFA district an address falls in. Useful for manual lookups and debugging.
Query params: address, jurisdiction (claimed)
Response: {"status": "accepted"|"denied"|"error", "claimed_jurisdiction": "...", "actual_jurisdiction": "...", "matched_address": "..."}
POST /api/upload-coupons Requires X-API-Key
Admin endpoint to replace the coupon dataset. Accepts .xlsx (preferred) or .csv via multipart upload or raw binary body. Saves locally, syncs to GCS bucket agromin-coupon-data, and forces a cache refresh. Changes take effect within seconds.
Auth: X-API-Key: $UPLOAD_API_KEY
Response: {"status": "success", "coupons_loaded": N}
GET /
Manual validation web form — HTML page for staff to hand-check a coupon + address in a browser. No auth required.
GET /health
Cloud Run health check. Returns {"status": "healthy"} with HTTP 200.

Coupon data

Source file

coupons.xlsx stored in GCS bucket agromin-coupon-data. Loaded at startup; cached in-process for 5 minutes. Admin uploads via /api/upload-coupons bypass the TTL immediately.

Required columns

Coupon — code string
Program Status — must be Active
Jurisdiction — city or county name
Start Date — M/D/YY or blank
End Date — M/D/YY or blank

Infrastructure

ComponentDetail
Shapefile CDTFA_TaxDistricts.gpkg — 26 MB, bundled in container, loaded at startup via GeoPandas. Heavy image because of GDAL system dependencies.
Geocoder ArcGIS World Geocoding Service. API key in ARCGIS_API_KEY env var.
GCS bucket agromin-coupon-data — coupon file storage. Authenticated via Cloud Run default service account.
CORS Allowed origins: shop.agromin.com, commercial.agromin.com, CIMcloud staging domains (*.agromin.mycimstaging.com, *.agromin.cimstaging.com).
Dockerfile python:3.11-slim + libgdal-dev, libgeos-dev, libproj-dev. Entrypoint: uvicorn main:app --host 0.0.0.0 --port 8080.

Deploy

The validator is deployed from the repo root (not the dispatch/ subdirectory):

# From repo root
gcloud run deploy coupon-validator \
  --source . \
  --region us-west1 \
  --project juris-coupon-valid \
  --allow-unauthenticated \
  --quiet

CI/CD: GitHub Actions builds on push to main → Docker → Artifact Registry → Cloud Run. The validator and dispatch services are deployed and versioned independently.
